Building dashboards

A dashboard is saved questions, shared filters, and an optional delivery schedule.

Sign in to save your place.

Picture it this way

A dashboard is a noticeboard. Each card is one question pinned to the board. A filter is a sticky note on the board, such as 'only this month', and each card can choose to obey that note. A subscription is the board arriving in someone's inbox on a schedule.

Cards, filters, and tabs

Create a dashboard in a collection, then add saved questions. Resize cards so the most important number is readable without scrolling on a laptop. Link a dashboard filter to each card that should obey it. A date filter does nothing until you connect it to a date column on that card. A text filter connected to the wrong field will silently show the unfiltered chart.

Current Metabase dashboards can use tabs when one page would be too long. Keep one decision on each tab. Click behavior can send a reader from a card to another dashboard or a question, filtered by the value they clicked.

Subscriptions are a data export

A subscription renders the dashboard and sends it. Anyone on that list sees the numbers even if they cannot sign in to Metabase. Treat the recipient list like a permission. Send a filtered subscription when a team should see one region, and confirm the filter is locked so they cannot widen it.

Alerts belong on a single question that crosses a line, such as a count of failed jobs. A dashboard subscription is the regular report. An alert is the exception.

Cache with a reason

Caching repeats a result so the warehouse is not hit on every view. A cached number can be stale. Set the cache where freshness is allowed to lag, and leave operational alerts uncached or on a short period.

From a filter to an inbox

Practice

Put two saved questions on one dashboard. Add a date filter and connect it to both. Open the dashboard, change the filter, and confirm both cards move. Then create a subscription to yourself and check that the filter you intended is the one that was sent.
