Administration

Groups, data permissions, collection permissions, sandboxes, and the audit log decide who sees which rows.

Sign in to save your place.

Picture it this way

Administration is the door list. Groups are the clubs. Data permissions say which tables a club may read. Collection permissions say which folders of questions they may open. A sandbox is a rule that a person only sees their own rows, even on a table the club can query.

People, groups, and two permission layers

Put people in groups. Grant access to groups, not to a long list of individuals. Data permissions control the database: which schemas and tables a group can view, and whether they can build native SQL or download results. Collection permissions control the saved content: view or curate.

A person can be allowed to query a table and still be blocked from a collection. Both layers have to say yes before they see a chart that uses that table. Admins bypass these layers. Keep the admin group small.

Sandboxes, SSO, and the audit

A sandbox, sometimes called row-level security in the product, adds a filter Metabase enforces for a group. Use it when one table holds many customers and each user may see only their rows. Test with a user in that group. An admin preview is not the test, because admins are not sandboxed.

SSO with SAML or JWT, sandboxes, and the audit log are paid features. The audit log answers who viewed or changed what. Turn it on when the data is sensitive enough that you will be asked. Impersonation, where Metabase connects to the warehouse as a database role that matches the viewer, is another paid path. Use it when the warehouse, not Metabase, should be the enforcement point.

Downloading is a copy

A group that can download results can walk away with those rows. Turn download off for groups that only need to look.

Practice

Create a group that can view one collection and one schema, and cannot download. Sign in as a user in that group. Confirm a curated question opens and a question in another collection does not. If you use sandboxes, confirm another customer's key returns no rows.
