Table design

Start with AUTO distribution, sort, and encoding. Override them when you can name the join, the filter, and the skew.

Sign in to save your place.

Picture it this way

Distribution is which waiter holds which orders. If two waiters must trade every plate to answer a question, dinner is slow. A sort key is the order of plates on one waiter's arm, so they can skip the ones that are obviously wrong. AUTO means you let Redshift watch the real questions and adjust those choices.

AUTO first, then a reason to override

New tables should start with automatic table optimization: DISTSTYLE AUTO, SORTKEY AUTO, and ENCODE AUTO. Redshift can change distribution and sort as it sees queries. That is the 2026 default, not a hint you add after a crisis. Override it when you already know the join key and the filter, and you have looked at skew.

CREATE TABLE analytics.orders (
    order_id BIGINT,
    customer_id BIGINT,
    ordered_at DATE,
    amount NUMERIC(12, 2)
)
DISTSTYLE AUTO
SORTKEY AUTO
ENCODE AUTO;

Interleaved sort keys are a legacy option. Prefer a compound sort on the columns you filter in order, or leave sort on AUTO. A sort key helps a WHERE on a prefix of that key. It does not help a function wrapped around the column.

Skew and encodings

Key distribution on a column that is almost always the same value parks the rows on one slice. That slice works while the others wait. Check skew before you congratulate yourself on a key. ALL is only for tables small enough to copy everywhere. A fact table marked ALL will waste storage and load time.

Encoding compresses columns. AUTO picks encodings. Do not hand-tune encodings on day one. Vacuum and analyze are largely automatic on current RA3 and Serverless warehouses. You still need to know the words, because an old cluster or a deleted-row heavy table can need a manual vacuum. Design the table so the load does not depend on a weekly rescue.
