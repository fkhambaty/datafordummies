Meet Snowflake

Snowflake is a cloud data platform. You do not install the database on your laptop.

Sign in to save your place.

Picture it this way

Think of a library. The books live in a warehouse that every reader can reach. The reading rooms are separate, and you can open a bigger room when the club arrives. A front desk checks cards, finds the shelf, and sends you to a room. Snowflake splits the job the same way: stored data, compute rooms called virtual warehouses, and a cloud-services desk.

Three layers, on purpose

Snowflake runs on a public cloud you choose: Amazon Web Services, Microsoft Azure, or Google Cloud. Snowflake manages the software. You cannot install the service on your own machines.

The architecture is a hybrid. Stored data sits in one central place, like a shared-disk database. Queries run on massively parallel clusters that do not share their compute with each other, like a shared-nothing database.

Layer What it does What you pay attention to
Database storage Holds table data, including Time Travel and Fail-safe bytes Storage grows when data changes and when history is kept
Compute Virtual warehouses run SQL, DML, loads, and Snowpark code Credits while a warehouse is running
Cloud services Sign-in, access control, metadata, optimization, and query dispatch A daily credit adjustment applies only after cloud services pass 10% of that day's warehouse usage

What a warehouse is, and is not

A virtual warehouse is a cluster of compute. It is not the place your tables are stored. Two warehouses can query the same tables at the same time without sharing CPU.

Warehouses come in two types, Standard and Snowpark-optimized. Snowpark-optimized warehouses are the ones Snowflake recommends when the work needs a lot of memory, such as machine-learning training. Ordinary SQL can use a Standard warehouse.

Each warehouse has a size. On Generation 1 warehouses the documented hourly credits start at 1 for X-Small and double at each larger size through 6X-Large. Generation 2 warehouses can bill differently, so read the current credit table before you estimate a bill. Credits are billed per second with a 60-second minimum.

Editions decide features, not curiosity

Each account has an edition: Standard, Enterprise, Business Critical, or Virtual Private Snowflake (VPS). Higher editions add features. They do not change the three-layer shape.

Standard includes virtual warehouses, resource monitors, one day of Time Travel, and Fail-safe. Enterprise adds multi-cluster warehouses, extended Time Travel up to 90 days, masking policies, row access policies, materialized views, search optimization, and query acceleration. Business Critical adds stronger network isolation, Tri-Secret Secure, and failover. VPS isolates the account from other Snowflake customers' hardware.

Unit prices also depend on region and on whether the account is On Demand or Capacity. This course does not invent a price. Use Snowflake's current pricing page for numbers.

Concept summary

  • Snowflake is hosted. You pick a public cloud and a region at account creation.
  • Storage, virtual warehouses, and cloud services are separate layers.
  • A warehouse burns credits while it runs. Storage is a different bill.
  • Edition controls features such as multi-cluster warehouses, 90-day Time Travel, and masking.
