Meet Kubernetes

Kubernetes runs containers. It does not replace the container runtime, and it does not install itself on a cloud until you ask a managed service to do that.

Picture it this way

A pod is one small boat. A node is the dock. The control plane is the harbour master who decides which dock gets the boat, and who sends a new boat if one sinks.

A cluster is two jobs

The control plane stores the desired state and makes decisions. The API server is the front door. etcd holds the cluster data. The scheduler picks a node. Controllers notice when the real world drifts from what you asked for.

A node runs the work. On the node, a kubelet talks to the API server, and a container runtime starts the containers. Your laptop can be one node. A cloud cluster is many nodes plus a control plane you often do not log into.

Piece What it decides What it does not do
Control plane Desired state, scheduling, and the API It does not run your app containers
Node Where pods are placed It is not a backup of etcd
Container runtime Starts and stops containers It is not the Kubernetes API

Pod, container, and virtual machine

A container is a process with its own filesystem view. A Pod is the Kubernetes object around one or more containers that share a network namespace and can share volumes. You almost never create a bare Pod for a long-running app. A Deployment owns that.

A virtual machine includes a guest operating system. A container shares the node's kernel. Kubernetes schedules Pods, not virtual machines. Some clusters run Pods inside lightweight VMs for isolation. That is a node setup choice, not a different API.

Versions move. Do not freeze a number in your head

The Kubernetes project publishes a new minor release about every four months. A minor version branch is maintained for about 14 months. Patch releases land on that branch.

This course does not name one patch as the version you must install. kubectl version and your cloud's version calendar are the numbers that matter. A tutorial that says "install 1.xx" without a date is already drifting.

Follow one request

kubectl sends the object to the API server. It does not start the container itself.

The API server checks the object and stores it. Controllers and the scheduler watch that store.

A kubelet on a node sees the Pod and asks the container runtime to start it.

Lab: read the words before you install

You do not need a cluster yet. Say which sentence is about a Pod and which is about a node.

Pod: the smallest object Kubernetes runs. It can hold more than one container.
Node: a machine, virtual or physical, that runs Pods.
Control plane: the API and the decision makers. Not where your web server process lives.

Concept summary

  • Kubernetes keeps desired state and tries to make the nodes match it.
  • A Pod wraps containers. A Deployment is what you usually want for an app.
  • Minor releases move. Check the release and the cloud calendar instead of a hardcoded patch.
