Task settings, mappings, and transforms

Table mappings are JSON selection rules. Transformations rename or drop columns. Task settings choose LOB mode, history, and validation. The defaults are not a design.

Sign in to save your place.

Picture it this way

The mapping is the list of boxes allowed on the truck. A transformation is a label maker that renames a box on the way. Task settings are the truck's rules: how heavy a box may be, and whether someone counts the boxes at the other end.

Selection rules

A selection rule includes or excludes a schema and a table. Rules run in order. A later exclude can remove what an earlier include added. Wildcards are convenient and dangerous. public.% on a PostgreSQL source will take tables you forgot, including ones the application still writes.

Start with an explicit include list for the first test. Widen it when the test is boring.

Transformations

A transformation can rename a schema, rename a table, rename or remove a column, or change case. It does not translate a stored procedure. That is schema conversion.

Adding a column with a transformation is a small, explicit change. Doing business logic in a DMS expression is how the migration becomes an untested program. Prefer a later SQL step you can review.

Knob If you leave the default
Table mapping You might move every table the wildcard matches

Rules, then rows

Include names the tables that may move.

A later exclude removes a table from that set.

Transforms change names on the way. They do not convert procedural code.

      "rule-action": "include"

      "rule-id": "2",

      "rule-action": "include"
    }
  ]
}

Concept summary

  • Mappings are ordered include and exclude rules.
  • Wildcards copy more than you think.
  • Transforms rename. They are not schema conversion.
