Full load

Full load copies the current rows. It does not, by itself, keep copying the changes that happen while it runs.

Sign in to save your place.

Picture it this way

Full load is emptying the shelves into the new shop once. If customers keep buying during the move, the new shop is already out of date unless you also run CDC.

What full load does

The task reads tables from the source and writes them to the target. Table mappings decide which tables. The target tables may already exist, or the task can be allowed to create them. For a heterogeneous migration, creating tables from DMS type mapping is a rough start. A converted schema from the schema lesson is usually the better target.

Large object columns have their own mode: do not copy them, copy them in limited size, or copy them fully. Full LOB mode is slower. The right mode is a business question about whether those columns matter. There is no universal size.

Speed and keys

DMS can split a large table into ranges when the engine and the table support it. A table with no key or no useful split column loads as one stream. Adding a key later does not rewind a finished load.

Indexes and foreign keys on the target slow the load. A common pattern is to load into a quiet target, then build secondary indexes, then turn on the constraints you still want. Do that from a written list, not from memory at cutover.

Choice Tradeoff
Full load only Simple. Misses changes made during the load.
Full load and CDC Copies current rows, then keeps going. Needs CDC prerequisites.
CDC only Copies changes from a position. Does not backfill old rows.

Concept summary

  • Full load is a copy of current rows, table by table.
  • Changes during the load need CDC if the target must catch up.
  • LOB mode and keys change speed and completeness.
