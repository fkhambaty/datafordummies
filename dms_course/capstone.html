Capstone

Write the cutover plan for one migration. You do not need an AWS account to finish the writing. You do need the decisions from the earlier lessons.

Sign in to save your place.

Picture it this way

The capstone is the moving-day list: which truck, which boxes, who keeps the diary, who counts, and who flips the shop sign. The sign flip is the application, not the task status.

The plan you will write

Name the source, the target, homogeneous or heterogeneous, the schema tool, the compute choice, the task type, the log you must retain, the validation you will read, and the person who changes the application connection string.

Include a rollback sentence. If CDC latency is not acceptable at the decision time, the application stays on the source. A running task is not permission to cut over.

A mapping you can explain

Use an explicit include list. Say which table you left out and why. If you need a rename, put it in a transformation and say so. Do not hide a rename inside a hope that the target table already matches.

Schema, load, and CDC happen while the application still uses the source.

Concept summary

  • Cutover is an application decision after the copy is caught up.
  • The mapping, the log, the latency, and the keys are the evidence.
  • A running DMS task is not the cutover.
