Lifecycle, import, moved, and removed

These blocks tell Terraform how to treat an object that already exists or that you renamed. They do not all exist on every old binary.

Sign in to save your place.

Picture it this way

import is writing an existing locker into the notebook. moved is changing the name in the notebook without throwing the contents away. removed is taking a line out of the notebook, and you must say whether the locker itself gets emptied.

lifecycle

prevent_destroy makes a plan fail instead of destroying that resource. create_before_destroy makes the new object first, which matters when a name must not have a gap. ignore_changes tells Terraform to leave listed arguments alone. Use it when something outside Terraform edits that field on purpose. It is also how drift hides. Review it.

replace_triggered_by replaces the object when another object changes. It is a lifecycle argument, not a cloud feature.

import, moved, and removed

An import block, added in Terraform 1.5, declares that an existing object should be recorded under an address. terraform plan -generate-config-out can draft HCL. Read the draft. Generated config is a start, not a style guide.

A moved block tells Terraform a rename. Without it, the plan destroys the old address and creates the new one. That is a real outage for a database.

A removed block, added in Terraform 1.7, drops an address from state. lifecycle { destroy = false } keeps the real object and forgets it. The default destroys it. Read the block before you apply.

OpenTofu started from code that already had import and moved. Later blocks and flags have diverged. The OpenTofu language page for your binary is the check. Do not copy a Terraform 1.10 snippet onto an old tofu and assume the keyword exists.

Block You want If you skip it
import Adopt an existing object Terraform offers to create a second one
moved Rename an address Destroy and create
removed Stop managing an object The next plan may still try to manage it

Rename without destroy

The state still has the old address.

The moved block tells plan this is a rename.

The same object keeps its cloud id under the new address.

Lab: read a moved block before you need one

Do not apply this against a real bucket. The point is the shape of the block.

moved {
  from = module.storage.aws_s3_bucket.logs
  to   = module.storage.aws_s3_bucket.audit_logs
}

removed {
  from = aws_instance.abandoned_lab
  lifecycle {
    destroy = false
  }
}

Concept summary

  • import adopts, moved renames, removed forgets.
  • Without moved, a rename is a destroy.
  • Check the binary before you use a block that landed in a later Terraform version.
