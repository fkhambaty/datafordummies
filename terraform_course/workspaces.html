Workspaces and environments

A CLI workspace is a separate state name inside one backend. An HCP Terraform workspace is a remote run environment. They share a word and not a meaning.

Sign in to save your place.

Picture it this way

CLI workspaces are extra notebooks in the same desk, all using the same shopping list. An HCP workspace is a different desk, with its own notebook, its own keys, and its own clerk. Calling both a workspace is how people apply the wrong notebook.

CLI workspaces

terraform workspace new dev creates a named state. terraform workspace select dev points the next plan at it. The configuration is the same. terraform.workspace returns the name so a config can branch. The default name is default.

This is a weak way to separate production from development. One directory, one set of files, and a selected name. The mistake is selecting the wrong name and applying. Many teams use separate directories or separate backend keys instead, so production is a different folder you have to mean to enter.

HCP Terraform workspaces

In HCP Terraform, a workspace is the remote object that holds variables, state, a run history, and permissions. It is not the CLI command terraform workspace. You can connect a CLI to one HCP workspace. Creating a second CLI workspace inside that remote setup is a different feature and easy to confuse.

OpenTofu does not gain HCP workspaces by using similar CLI flags. HCP Terraform runs HashiCorp's product. If a team standardizes on tofu, they need a runner that executes that binary. Pointing an HCP workspace at the code does not switch the binary for you.

terraform workspace A state namespace in the backend A separate permission boundary
HCP Terraform workspace A remote run, with variables and state The OpenTofu control plane

Lab: list CLI workspaces without creating a second cloud

From a lab directory that already ran terraform init. Do not select a workspace you do not understand in a directory that has real cloud resources.

terraform workspace list
# default is the one you already have
# terraform workspace new lab-only
# terraform workspace select default

Concept summary

  • CLI workspaces are state names. The config stays the same.
  • HCP Terraform workspaces are remote run environments.
  • Separate directories are often clearer than a workspace switch for production.
